| REQ-1 | The repository provides a reproducible local Windows workspace with recorded Rust/npm toolchain metadata, committed Cargo/npm lockfiles, and documented setup, check, test, and production-build commands. | A lockfile-based install followed by the documented aggregate command succeeds on the local Windows development environment and builds both native Rust crates and the production web bundle. `test:workspace-clean-build` | 1.1, 4.1, 4.2 |
| REQ-2 | A Rust-owned toy clock advances only through configured fixed ticks and supports pause, resume, one-tick step, reset, injected scheduler ticks, and telemetry. | Initial/reset state is paused; pause/resume are idempotent; step while running is rejected without mutation; `tick` and `tick_duration_us` are `u64`, with checked `simulation_time_us`; each worker callback queues one tick with no catch-up; pause cancels future callbacks while queued events finish in order; disposal terminates immediately and rejects pending work; replaying identical commands plus injected ticks produces byte-identical telemetry. `test:toy-clock-determinism` `test:worker-scheduler` | 1.2, 2.1, 2.3, 4.2 |
| REQ-3 | Rust owns a versioned tagged JSON application protocol with request correlation, generated TypeScript declarations, telemetry, and explicit typed errors; TypeScript transport lifecycle remains outside that protocol. | Generated declarations match committed output; unknown versions, malformed JSON, unknown commands, invalid payloads, step-while-running, and overflow return typed errors without mutating clock state. Inputs without a usable request ID return an explicitly uncorrelated error. `test:protocol-contract-sync` `test:protocol-invalid-input` | 1.2, 1.3, 2.1, 2.3, 4.1, 4.2 |
| REQ-4 | Rust/WASM inside one module Web Worker is the sole clock authority, while TypeScript owns scheduler and transport lifecycle. | Boundary tests prove client-owned starting/stopped, worker-emitted ready/failed, one timer, serialized requests/ticks, pre-ready rejection, request correlation, disposal cleanup, pending-request rejection, worker termination, ignored late replies, and no implicit restart. `test:worker-boundary` `test:worker-scheduler` | 2.1, 2.2, 2.3, 4.2 |
| REQ-5 | A minimal vanilla TypeScript/Vite/Babylon.js shell exposes the clock, controls, and a learner-facing protocol diagnostic. | Playwright Chromium proves a live canvas, lifecycle status, tick/time telemetry, pause/resume, exact one-tick step, reset, and a collapsed diagnostics panel that sends an unsupported raw envelope through the real worker path and displays its typed error, correlation, and unchanged clock state. `test:foundation-browser-flow` | 2.2, 2.3, 4.2 |
| REQ-6 | Non-interactive root commands run every accepted quality check locally without hosted CI. | Rust format/lint/tests, TypeScript type checks/unit tests, declaration drift, exercise-pack contract, production build, and Playwright Chromium tests pass through documented root commands; no GitHub Actions or CI configuration is introduced. `test:quality-gates` | 1.1, 1.3, 4.1, 4.2 |
| REQ-7 | The foundation includes a learning-first chapter with beginner Rust guidance and a runnable experiment. | The chapter contains architecture and sequence diagrams, setup/troubleshooting, ownership/borrowing, crate boundaries, WASM/JSON serialization, worker concurrency, simulation versus render time, rationale, exact acceptance limits, and a pause/step/reset experiment with expected observations. `file:docs/learning/01-executable-foundation.md#exists` `file:docs/learning/01-executable-foundation.md#contains:## Run the experiment` `review:cr` | 3.1, 4.2 |
