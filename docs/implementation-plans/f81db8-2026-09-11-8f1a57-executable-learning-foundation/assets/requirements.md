# Requirements

<!-- Every discovered edge case belongs in this table, assets/risks.md, or an explicit non-goal in assets/intent.md. -->

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | The repository provides a reproducible local Windows workspace with recorded Rust/npm toolchain metadata, committed Cargo/npm lockfiles, and documented setup, check, test, and production-build commands. | A lockfile-based install followed by the documented aggregate command succeeds on the local Windows development environment and builds both native Rust crates and the production web bundle. `test:workspace-clean-build` | 1.1, 3.1, 3.3 |
| REQ-2 | A Rust-owned toy clock advances only in configured fixed ticks and supports pause, resume, one-tick step, reset, and telemetry. | Wall time does not change paused state; one step advances exactly one tick; reset returns tick and time to zero; replaying an identical command sequence produces byte-identical telemetry. `test:toy-clock-determinism` | 1.2, 2.3, 3.3 |
| REQ-3 | Rust owns a versioned tagged JSON protocol with request correlation, generated TypeScript declarations, telemetry, and explicit typed errors. | Generated declarations match committed output; unknown versions, malformed JSON, unknown commands, and invalid payloads return typed errors without mutating clock state. Inputs without a usable request ID return an explicitly uncorrelated error. `test:protocol-contract-sync` `test:protocol-invalid-input` | 1.2, 1.3, 2.1, 2.3, 3.1, 3.3 |
| REQ-4 | Rust/WASM inside one module Web Worker is the sole clock authority, and worker lifecycle is visible to the UI. | Boundary tests prove starting, ready, failed, and stopped behavior; request correlation; pre-ready rejection; and that UI code cannot directly advance or mutate core state. `test:worker-boundary` | 2.1, 2.2, 2.3, 3.3 |
| REQ-5 | A minimal vanilla TypeScript/Vite/Babylon.js shell exposes the clock and its controls. | Playwright Chromium proves a live canvas, lifecycle status, tick/time telemetry, pause/resume, exact one-tick step, reset, and a visible protocol-error state. `test:foundation-browser-flow` | 2.2, 2.3, 3.3 |
| REQ-6 | Non-interactive root commands run every accepted quality check locally without hosted CI. | Rust format/lint/tests, TypeScript type checks/unit tests, declaration drift, production build, and Playwright Chromium tests pass through documented root commands; no GitHub Actions or CI configuration is introduced. `test:quality-gates` | 1.1, 1.3, 3.1, 3.3 |
| REQ-7 | The foundation includes a learning-first chapter with beginner Rust guidance and a runnable experiment. | The chapter contains architecture and sequence diagrams, setup/troubleshooting, ownership/borrowing, crate boundaries, WASM/JSON serialization, worker concurrency, simulation versus render time, rationale, exact acceptance limits, and a pause/step/reset experiment with expected observations. `file:docs/learning/01-executable-foundation.md#exists` `file:docs/learning/01-executable-foundation.md#contains:## Run the experiment` `review:cr` | 3.2, 3.3 |
